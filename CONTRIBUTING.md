# Работа с изменениями

1. Создайте ветку задачи от актуальной `main`.
2. Используйте отдельную синтетическую SQLite-базу и мокированный Telegram-транспорт.
3. Выполните команды проверок из README. Для полного набора установите
   закреплённые зависимости с проверкой хешей.
4. Откройте Pull Request и дождитесь `Quality` и `Secrets (Gitleaks)`.

Изменения транспорта требуют проверки закреплённых версий и их интерфейсов.
Реальная авторизация Telegram и отправка сообщений не являются частью CI.

Настройки владельца, данные и секреты должны оставаться вне Git.
Исполняемый UI хранится в `dealradar/web`; сборка сайта синхронизирует резервные
файлы `site/assets`. Для проверки этого контракта выполните `node site/build.mjs`
с собственными локальными настройками или синтетическим примером.

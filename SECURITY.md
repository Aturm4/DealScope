# Безопасность и личные данные

В репозитории находятся исходники, тестовые фикстуры, примеры настроек и
скриншоты с вымышленными объявлениями.

Личные базы SQLite, WAL/SHM, Telegram-сессии, токены, API hash, одноразовые коды,
логи, резервные копии и настройки действующего сайта не предназначены для Git.
Они исключены правилами `.gitignore`. Перед публичной отправкой также
проверяется история Git.

## Использование

- Реквизиты вводятся вручную в своей консоли, без записи терминала и передачи
  через аргументы команд. CI не входит в Telegram и не отправляет уведомления.
- Пользовательская сессия Telegram имеет широкие права аккаунта. Ограничения
  RPC в коде задают поведение приложения; они не сужают права украденного ключа.
- Сессия и токен бота хранятся в RAM. Это не защищает от чтения памяти,
  заражённой ОС или привилегированного процесса.
- SQLite содержит незашифрованные личные данные, включая исходные тексты
  объявлений. Храните базу локально и проверяйте состав резервных копий.
- После остановки проверяйте подтверждение выхода. При неуспехе отзовите
  **Personal Deal Radar** с доверенного устройства Telegram.
- Приватный Sites-компаньон должен оставаться доступным только владельцу.

## Сообщение об уязвимости

Свяжитесь с автором через контакты [профиля Aturm4](https://github.com/Aturm4).
Не прикладывайте реальные токены, коды входа, сессии, личные базы или данные
аккаунта к публичному Issue. Для воспроизведения используйте синтетические данные.

## Проверки публикации

Перед первой загрузкой проверяются исходная локальная история и чистый
публичный снимок. CI запускает Gitleaks с маскированием значений, без исключения
каталога тестов и без inline-разрешений `gitleaks:allow`.
Проверка сканером ограничена его правилами; состав отправляемых файлов
дополнительно проверяется вручную.
